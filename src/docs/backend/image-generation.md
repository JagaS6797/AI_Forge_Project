# Image Generation Workflow

## Scope

How image-generation intent is detected in chat, how images are created through the model provider, and how generated images are returned to the UI as attachments.

## Current Implementation

- Endpoint(s):
  - POST /api/chat
  - GET /api/chat/images/{attachment_id}
  - GET /api/chat/attachments/{attachment_id}
- Service(s):
  - app/services/image_generation_service.py
  - app/services/chat_service.py
- Schema(s):
  - app/schemas/chat.py
  - app/schemas/attachment.py
- Model(s):
  - app/models/file_attachment.py
- Frontend component(s):
  - components/chat/InputBar.tsx (Generate Image mode)
  - components/chat/ChatWindow.tsx (attachment event handling)
  - components/chat/MessageAttachments.tsx
- Frontend API binding(s):
  - sendMessage()
  - downloadAttachment()

### Intent Detection Rules

- Explicit command prefixes are supported:
  - /image <prompt>
  - /imagine <prompt>
- Natural language requests are inferred when image action + image subject words are both present.
- Prompt cleanup removes polite prefixes and action boilerplate where possible.

### Provider and Persistence

- Uses AsyncOpenAI client configured by image_gen_model.
- Accepts either b64_json payloads or URL payloads from provider.
- Generated bytes are saved through existing attachment storage service.
- A file_attachments row is persisted for the generated image.

## Step-by-Step Flow

1. User selects Generate Image mode and submits prompt text.
2. Frontend normalizes outgoing message to /image <prompt> when needed.
3. Chat endpoint starts stream and detects image-generation intent.
4. Backend calls image provider with prompt and selected model.
5. Backend decodes/downloads image bytes and saves attachment metadata.
6. Backend streams assistant token confirming generation.
7. Backend streams attachment event with generated image metadata.
8. Backend persists assistant message linked to generated attachment_id.
9. Backend emits done=true to close stream.

## API Contract

- Request: { message, thread_id, attachment_ids, rag_enabled }
- Stream events for image path:
  - { token: "Image generated successfully..." }
  - { attachment: { id, file_name, file_type, file_size, created_at } }
  - { done: true }

## State and Data Impact

- Created/updated data:
  - file_attachments row for generated image
  - assistant chat_messages row with attachment_ids=[generated_id]
- Frontend state:
  - assistant message receives streamed attachment metadata
  - attachment appears in message attachment renderer

## Error Handling

- Empty image payload from provider raises OpenAIError path.
- Provider/API errors are streamed as user-visible token text.
- If assistant persistence fails, stream still completes with done=true.
- Image byte download failures from provider URL path raise streamed error token.

## Security and Compliance Notes

- Image download/view endpoints require owner validation.
- Generated assets are stored under user ownership.
- File metadata only is streamed; local storage path is not exposed.

## Enhancement Hooks

- Add configurable image dimensions/style parameters from UI.
- Add image moderation checks before persistence.
- Add deduplicated prompt/result cache for repeated prompts.
